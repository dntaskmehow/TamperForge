TamperForge is a compact Python toolkit for generating dynamic SQLMap tamper scripts from live NIST National Vulnerability Database telemetry. It queries recent WAF bypass and parser differential CVEs, automatically synthesizing functional Python `tamper()` modules[cite: 5] to give security engineers a predictable build path from vulnerability intelligence to offensive tooling.

## Overview

The project is intentionally small and practical: an automated query pipeline plus a script generator. It keeps the workflow focused on the real value proposition of advanced testing: extract parser quirks once, compile them into executable SQLMap modules, and integrate them into your scanning pipelines without hand-writing boilerplate.

### What it does

- Queries the NIST NVD API for telemetry on specific WAF bypass and parser differential CVEs[cite: 4, 5].
- Extracts bypass patterns and string replacement logic[cite: 4].
- Generates a production-ready Python script with a standard `tamper(payload, **kwargs)` function[cite: 4, 5].
- Outputs the forged script to a target file through clean CLI arguments[cite: 4].

### Who it is for

- Penetration testers and red teams building custom WAF bypass chains.
- Security researchers who want a consistent way to generate SQLMap extensions from CVE data.
- Automated testing systems that need a lightweight vulnerability-to-payload compiler pattern.

## Why it exists

In offensive security, the challenge is not just reading a vulnerability advisory, but turning that advisory into something executable and testable against hardened perimeters. TamperForge addresses that by providing a simple compiler boundary: a clear CVE input contract, deterministic script output, and a fast path from vulnerability intelligence to code.

The current implementation is deliberately minimal and transparent, which makes it easy to extend for richer payload patterns, stronger validation, or more advanced tamper generation workflows.

## Key capabilities

- Reliable NIST NVD telemetry extraction for recent CVE bypass patterns[cite: 4, 5].
- Small, readable codebase focused on a single generation flow.
- CLI-first workflow for local script synthesis and automation.
- Extensible structure for future WAF bypass vector expansion.

## Architecture

```text
Target CVE ID (e.g., CVE-2026-XXXX)
      ↓
fetch_cve_bypass_patterns()
      ↓
Generated SQLMap Python tamper module
      ↓
tamper(payload, **kwargs)

```

The core implementation is intentionally narrow:

* `tamper_forge.py` contains the NIST API querying and script generation logic.
* Output scripts integrate directly with SQLMap's `--tamper` execution flag.

## Quick start

Run the generator specifying your target CVE:

```bash
python3 tamper_forge.py --cve "CVE-2026-1337" --output "forged_bypass.py"

```

This creates a Python file similar to:


## Usage example

```bash
python3 tamper_forge.py --cve "CVE-2026-XXXX" --output "cve_tamper.py"
sqlmap -u "[http://target.local/vuln.php?id=1](http://target.local/vuln.php?id=1)" --tamper="./cve_tamper.py" --batch

```

A generated tamper module is a standard SQLMap script; the exact execution behavior depends on your target's WAF configuration and parameter structure.

## Configuration and inputs

The current generator reads the `--cve` argument to target specific vulnerability telemetry and outputs a standardized script path via `--output`. That is the primary contract today.

```bash
python3 tamper_forge.py --cve "CVE-2026-XXXX" --output "forged_bypass.py"

```

The tool then synthesizes the bypass patterns into a structured Python module with a predefined priority level.
